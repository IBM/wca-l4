    BOB DEMO-BUILDER MODE

    SETUP AND REGISTRATION

    i. What you're building toward

    Within this chapter, you will assemble the Demo Builder environment end-to-end:

    • Install the Client Engineering Bob Marketplace extension
    • Create the GitHub Personal Access Token (PAT) that unlocks its catalog
    • Stand up a fresh project workspace; and
    • Install the IBM Pre-Sales Demo Builder itself: the packaged Mode, Skills, and MCP servers that the remainder of this lab runs upon

    The illustration above serves as a one page map of the setup work ahead. Follow along in the subsequent steps for detailed, step-by-step guidance (with links and highlighted screen captures throughout.)

    ii. Before you start

    • IBM Bob is installed and open
    • You can sign in to github.ibm.com
    • Your IBMid credentials are at hand
    • You are connected to the IBM Intranet (or via Cisco AnyConnect VPN)
    • A local folder is available to serve as your Bob project workspace

    No additional downloads or staged files are required before you begin.

    iii. Hands-on: Install the CE Bob Marketplace & Demo Builder

    The work ahead proceeds in four phases: download the Marketplace extension; create the GitHub PAT that authenticates it; install the extension and register your token; and, finally, install the Demo Builder into a fresh workspace.

    1. Start by navigating to the following page within a web browser:

      https://github.ibm.com/ClientEngineering/bob/tree/main/How-To/Bob-Marketplace

    1. Scroll down to the Installation Guide subsection and click the link under Step 1 - Download the extension:

      https://github.ibm.com/ClientEngineering/bob/blob/main/Extensions/Bob-PreSales-DEMO-Builder-Marketplace.vsix

    1. You will be redirected to the extension's file page. Click the Download raw file button (the arrow pointing downwards.)

    1. Click README.md (under How-To/Bob-Marketplace in the File Explorer on the side).

      This redirects you to https://github.ibm.com/ClientEngineering/bob/blob/main/How-To/Bob-Marketplace/README.md (alternatively, you may follow that link directly).

    1. Back on the README page, scroll down until you reach Step 2 - Create a GitHub API Token.

    1. Click the link: https://github.ibm.com/settings/tokens/new

    1. Assign your GitHub PAT a name that you will recognize later. Populate the Note field with Bob Marketplace or something similar.

    1. Expand the Expiration field and select 90 days.

    1. Under Select scopes, toggle on (checkmark) the repo option. This will automatically select the nested options (repostatus, repo_deployment, etc) as well.

    1. Leave all other settings at their defaults. Scroll to the bottom of the page and click the green Generate token button.

    1. Press the copy button (the two overlapping squares) to copy the newly-generated GitHub Personal Access Token (PAT) to the clipboard.

    1. Paste and save your GitHub PAT within a password manager (or, less securely, within any text editor).

      RETAIN YOUR CREDENTIALS DOCUMENT

      You will paste this token into Bob shortly — but do not delete it once you have done so. The saved credentials are your first resort for troubleshooting later in this chapter.

    To complete the tasks detailed throughout this module, you will make use of three Bob Custom Modes. Each has been packaged for a frictionless, one-click install from the Bob Marketplace for Client Engineering.

    First, the Marketplace extension itself must be installed:

    1. Within the Bob IDE, click the Extensions tab from the left-hand side of the interface (or alternatively press Ctrl+Shift+X).

    1. The Extensions panel will open. In the top-right corner of the panel, next to the circular (loop) icon, click the three-dotted icon (...) to open a drop-down menu of additional options.

      Click Install from VSIX...

    1. Within the File Explorer, select Bob-PreSales-DEMO-Builder-Marketplace.vsix — the file you downloaded earlier when you pressed Download raw file. Likely this file is sitting in your local Downloads folder.

      Click the Install button to continue.

    1. Client Engineering Bob Marketplace should now appear within the Installed section of the Extensions panel.

      Take note that a Marketplace icon has also appeared along the tabs on the left-hand sidebar of the Bob IDE.

    1. Click the CE Bob Marketplace tab from the sidebar.

    1. Click the triangular > icon next to the Collections drop-down to expose the contents.

    1. The IBM Pre-Sales Demo Builder extension will appear under the Collections dropdown. Double-click it to open a detailed panel view.

      • Before the extension can be installed, register the GitHub PAT created earlier
      • Click the small key icon (Bob Marketplace: Set Repository Token) near the top of the CE Bob Marketplace panel

    1. An input window expands at the top of your screen, within the IBM Bob search bar.

    1. Copy and paste the GitHub PAT into the input window and press Enter to continue.

    1. A "Token saved [...]" notification will appear in the bottom-right portion of your screen.

    1. Next, a project workspace must be established.

      Click the Explorer tab from the Bob IDE sidebar.

    1. Click Open Folder.

    1. Create a New folder and name it Bob L3 Demo Builder.

    1. Highlight (click once) the newly-created folder and then press Select folder.

    1. Click "Yes, I trust the authors" when prompted to do so.

    1. From the Bob IDE sidebar, click the "CE Bob Marketplace" tab.

    1. Expand Collections once again by pressing the > icon.

      Click Install next to IBM Pre-Sales Demo Builder to continue.

    1. Click Install on the pop-up window that appears.

    1. A notification in the bottom-right corner of the Bob IDE will confirm that the install was successfully completed.

      Next, click the Explorer tab.

    1. Take note of the .bob folder that has been installed automatically into your project. This contains all of the components needed to complete this hands-on lab and demo-builder exercises. You will recognize the pattern from Module 3 | Tailor: Modes, Rules, and Skills, distributed as version-controlled files within .bob/.

    iv. Validation

    At this point, you have: installed the Client Engineering Bob Marketplace; created a GitHub PAT and linked it to the Marketplace; and installed the Demo Builder.

    Before proceeding, verify each of the following items:

    • Client Engineering Bob Marketplace icon is visible
    • GitHub API token is configured
    • Marketplace catalog loads successfully
    • Modes are visible
    • Skills are visible
    • MCP Servers are visible

    v. Connect the MCP servers

    The Demo Builder relies upon two MCP servers:

    • TechZone (environment provisioning and documentation)
    • Carbon (IBM's design system)

    Each seerver requires a short-lived credential from users (like yourself) for access. Gather these first:

    CREDENTIAL WHERE TO GET IT
    TechZone API token Your TechZone profile page: techzone.ibm.com/my/profile
    Carbon authorization code The Carbon MCP IBMid flow: mcp.carbondesignsystem.com/mcp/auth/ibmid/web
    GitHub PAT Already recorded in the previous section

    THESE KEYS ARE IMPERMANENT — BY DESIGN

    The credentials you have just gathered are time-sensitive:

    • Your TechZone API key resets every time you re-log into TechZone
    • Your Carbon authorization code resets every 2 hours

    If you are experiencing issues with the MCP servers:

    1. Re-log into TechZone and Carbon, and gather all 3 credentials again
    2. Paste the following message in the IBM Bob Agentic Sidebar, in Agent mode, with your fresh credentials appended:
    Please test the Carbon and MCP servers and ensure they are working. Here are my credentials:

    With all of the necessary credentials generated and recorded, perform the following steps:

    1. Activate the Agentic Sidebar by clicking the Bob icon at the top of the IDE interface (just to the right of the search bar).
    1. Use the Mode toggle button to activate Agent Mode.

    1. Copy the following prompt to your clipboard. Before executing the instruction within the Agentic Sidebar, modify Line 2 and Line 3 to replace <PLACEHOLDER> with your TechZone and Carbon MCP server credentials.

      When ready, paste the modified prompt into the Agentic Sidebar and press Enter to execute.

      1
2
3
      Configure the TechZone and Carbon MCP servers and help me verify they are connected. Here are my keys:
TechZone: <PLACEHOLDER>
Carbon: <PLACEHOLDER>
      ALTERNATIVE: MANUAL MCP CONFIGURATION

      Should you prefer to wire the MCP servers by hand (or need to troubleshoot what Bob configured on your behalf), the TechZone MCP configuration JSON is published at github.ibm.com/ClientEngineering/bob — techzone-mcp-config.json. Copy its entire contents into your Project MCPs configuration and save, then verify that the techzone request and techzone documentation servers appear. A quick functional test: prompt Bob to list environments, search for StudentID environments, and request a 1-day test environment.

    vi. Key takeaways

    • The CE Bob Marketplace is the distribution channel for Client Engineering's packaged assets — Modes, Skills, and MCP servers are installed as a VSIX extension
    • A GitHub PAT (with repo scope and a 90-day expiry) is the key that unlocks the Marketplace catalog; store it within a password manager and expect to refresh it periodically
    • Installing the IBM Pre-Sales Demo Builder places a complete .bob/ folder into your workspace
    • The TechZone and Carbon MCP credentials are deliberately short-lived; when MCP calls misbehave, regenerating fresh credentials is the first remedy to attempt
    • Validate the complete chain (Marketplace, token, catalog, Modes, Skills, and MCP servers) before any demo work begins


    With the environment assembled and validated, we will shift our attention to the discipline that shapes demo quality more than any other: effectively briefing and prompting the Demo Builder itself.
